# 09 部署、运维与安全上线清单

## 环境分层
- 本机：SQLite、DEBUG=true、127.0.0.1，仅供开发。
- 测试服务器：PostgreSQL、独立测试用户和假数据；HTTP 8080 仅受信任网络试运行。
- 生产：独立配置、生产数据库、经审计的备份和恢复策略、内网 TLS、受控访问。

## PostgreSQL Compose 测试部署
从项目根目录复制 `.env.docker.example` 为 `.env`，设置强随机 `DJANGO_SECRET_KEY`、`DB_PASSWORD`（演示配置建议使用 URL 安全的字母数字组合）、`DJANGO_ALLOWED_HOSTS` 为真实内网主机名/IP。

从 `deploy/` 目录：
```bash
docker compose --env-file ../.env up -d --build
docker compose --env-file ../.env ps
docker compose --env-file ../.env logs --tail=80 web
docker compose --env-file ../.env exec web python manage.py createsuperuser
```

访问 `http://<内网地址>:8080`。**此模式没有 HTTPS，不得公网开放，也不要录入真实客户机密。**

## 正式上线前必须完成
- [ ] 启用可信 HTTPS 反向代理；配置 HSTS、`DJANGO_SECURE_COOKIES=true`、可信 Host/Origin，并验证 Nginx 的可信代理头。
- [ ] 关闭 DEBUG；生产密钥通过机密管理注入，禁止放在 Git。
- [ ] 执行 `python manage.py check --deploy` 并处理所有有效警告。
- [ ] 登录失败限流与管理员 MFA/身份策略；严格限制 Django Admin。
- [ ] 增加文件访问鉴权（本工程不提供上传接口）；上传大小与类型限制、恶意文件扫描。
- [ ] Dify 与数据库仅在后端网络可达；不对客户端开放数据库端口。
- [ ] 设置结构化业务日志、可追溯审计、告警与基本监控。
- [ ] PostgreSQL 每日定时备份与附件备份，备份应离开业务主机；定期恢复演练。
- [ ] 制定版本回滚步骤、数据库迁移兼容性和停机变更窗口。
- [ ] 审核原始合同/客户资料是否允许传给第三方模型。

## 备份示例（仅手动演示）
在 `deploy/` 目录运行，注意备份中可能含敏感数据，文件应安全保存：
```bash
docker compose --env-file ../.env exec -T db pg_dump -U workbench -d workbench -Fc > workbench.dump
```
还需备份授权文件存储、应用配置（不与源码一同泄露）及密钥恢复材料。

## 回滚原则
应用回滚不等于数据库回滚；迁移采用可前向兼容的方案。生产变更必须先在测试环境演练，必要时通过备份恢复，不要直接对生产数据执行不可逆迁移。
