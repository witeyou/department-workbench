# 07 测试规范与业务验收

## 每次开发任务的完成定义（DoD）
- 所有 UI 关键操作可通过浏览器走通；列表能筛选、分页，新增详情能回查。
- 新增模型有迁移；迁移不破坏历史数据；数据库约束真实生效。
- 关键 service 层有单元测试；业务流程有集成测试；权限有反向案例。
- 文本输入安全输出转义，更新操作仅 POST/PATCH，具有 CSRF 保护。
- 运行 `uv run ruff check .`、`uv run python manage.py check`、`uv run pytest -q`、`uv run python manage.py makemigrations --check --dry-run` 均通过。
- 文档更新页面入口、操作方式、已知限制和下轮依赖；不以虚假数据演示领导 KPI。

## 测试分类
1. **模型**：唯一编号、必填字段、索引、外键约束、非法状态值。
2. **业务服务**：状态转移合法性、审批边界、任务指派、状态重试与幂等。
3. **权限**：匿名、本对象、同组非本人、跨组、领导、后台维护者；包括列表、详情、导出、附件。
4. **视图**：GET/POST、参数校验、分页、搜索、错误展示、CSRF。
5. **并发**：两个用户同时创建编号、同时接受评估；尽可能使用 PostgreSQL 复测。
6. **集成**：市场询盘 → 申请评估 → 分配 → 答复 → 确认 → 历史可查。
7. **AI**：超时、429/5xx、非 JSON、Schema 不匹配、人工拒绝建议、重复触发；业务记录保持不变。
8. **部署**：本机 SQLite 和 Compose PostgreSQL 启动、迁移、健康检查、备份与恢复。

## 场景验收

### A. 市场流程
给定真实的产品询盘描述，市场人员能创建客户和询盘、更新跟进情况；在商机模块交付后还能更新商机阶段和跟进记录，市场负责人能查看组内积压项。其他部门人员不能读取未经授权的商业字段。

### B. 售前技术评估
提交→分配→评估→答复→市场确认。验证责任人变化、状态合法性、超期指标和不可篡改的动作记录。

### C. 研发流程
创建产品和版本，建立标准研发/定制项目，关联需求、里程碑和任务，验证任务负责人修改、阻塞与逾期追踪。

### D. 领导驾驶舱
所有 KPI 基于数据库真实记录，点击可下钻；列表与汇总使用同一权限范围；空库时不展示伪造数据。

### E. AI 草稿确认
模型输出不能直接改变正式需求、评估结论、项目状态；用户修改确认后才通过 service 提交，整个事件被记录。

## 试点结束验收口径
- 关键市场→研发流程无需重复跨系统填报。
- 指派和反馈责任人能够追溯。
- 查询项目状态及超期需求无需手工整理日报。
- 生产账号、数据库、文件及 AI Token 在授权范围内可控。
