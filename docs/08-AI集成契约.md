# 08 AI / Dify 接入契约（V0.4 开发，不属于初始骨架）

## 功能边界
- 询盘智能整理：生成结构化需求摘要、产品匹配、待确认问题。
- 技术评估辅助：基于允许访问的知识库产生候选方案和待确认事项。
- 任务草稿：根据已接受需求生成候选任务，用户审核后再创建。
- 项目摘要：由 Django 查询并计算事实数据，Dify 负责文字解释。

## 推荐调用流
1. Django 确认调用人具有目标业务对象访问权限。
2. Django 组装最小必要输入，移除不需要的个人信息与商业机密。
3. Django 后台通过固定 Dify Workflow API 调用，并产生 AIJob 记录。
4. 返回内容采用 Pydantic / JSON Schema 验证；保存 AIResult（draft）。
5. 显示建议，用户修改与确认后通过业务 Service 更新；记录审核人与时间。
6. 超时/无效输出显示可重试提示，原业务记录不被修改。

## 询盘分析 JSON 示例

```json
{
  "schema_version": "1.0",

  "requirement_summary": "需要特殊统计分析功能",

  "unknowns": ["统计周期", "验收标准"],
  "risk_flags": ["可能涉及软件定制"]
}
```

## API 安全
- 后端以服务凭据调用固定工作流，不将 Dify API Key 下发浏览器。
- 明确工作流版本、请求超时、重试次数、幂等键、请求审计 ID。
- 阻止 SSRF（用户不可控制服务端任意访问 URL）；模型不能自由触发未经授权的业务写操作。
- 对日志进行个人信息、合同信息脱敏；确认第三方模型 API 是否允许传输客户资料。
- 不向模型开放原始数据库连接或直接 SQL 执行。

## 验收
工作流失败时，系统其他功能正常；AI 结果可审核与撤销；自动创建任务只能先作为草稿；结果来源、时间和处理人可追溯。
