# 05 界面规范

## 导航结构
工作首页 / 市场业务 / 技术评估 / 统一需求 / 产品研发 / 定制项目 / 我的任务 / 管理驾驶舱 / AI 辅助 / 管理设置。

## 页面约束
- 优先使用 Django Templates，复杂交互再局部引入 HTMX（静态资源必须本地托管，保证内网可用）。
- UI 样式建议 Bootstrap 5，首次启动骨架使用极简自带 CSS；引入时保持统一布局与响应式规则。
- 业务页优先实现 **列表 → 详情 → 创建/编辑 → 状态流转 → 操作历史**，再考虑看板/统计。
- 列表包含关键词、状态、负责人、日期范围筛选和分页；每页默认不超过 20–30 条。
- 详情展示元数据、关联对象、评论、附件、审批记录；变更操作单独提供按钮和确认页面。
- 用户必须知道自己当前的角色、对象状态和下一步允许的操作。
- 不能使用硬编码/伪造的 KPI 数据；无数据展示“暂无数据”。
- 可访问性：标签关联输入、按钮文案明确、对比度满足常规可读要求、表单错误有文字说明。
- 所有 POST 表单带 CSRF，修改操作不使用 GET。

## 项目统一风格
简洁、浅色、表格与状态为主；不使用装饰图形替代业务信息；移动端用于查看与轻量处理，桌面端用于数据录入和管理。
